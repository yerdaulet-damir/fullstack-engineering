# Contributing

Contributions should make a project more runnable, more testable, or more accurate.

Good pull requests include:

- A repaired or replaced dead reference with a reason.
- A smaller starter that preserves the same learning constraint.
- An acceptance test for a failure mode the project currently misses.
- A browser, database, deployment, or AI engineering exercise grounded in a reproducible bug.
- A current primary source replacing an old secondary tutorial.

Do not add:

- Generic career advice.
- Tool lists without a project that needs them.
- Generated summaries of documentation.
- Certificates, grading systems, or motivational filler.
- A new framework version of an existing project without a different engineering constraint.

Run `pnpm check:catalog` before opening a pull request. Explain what a developer can now build or verify that they could not before.
